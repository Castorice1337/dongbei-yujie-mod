# Milestone Audit: v1.0

## Verdict

**Status:** gaps_found

The milestone is close to the intended playable loop and the current code builds, but it should not be archived as fully complete yet. Three milestone requirements have behavior-level gaps against the original v1 definition of done:

1. `FOOT-04`: Big Sweaty Foot no longer applies Daipai on melee hit.
2. `YUJI-03`: Dongbei Yujie does not actively target players for melee attacks.
3. `YUJI-07`: Yujie spawning is not implemented as controlled attempts within 24 blocks of players.

There are also process/documentation gaps: Phases 2, 3, and 4 lack standard `*-VERIFICATION.md` files, and project-facing docs still describe some completed resource work as pending.

## Critical Gaps

### FOOT-04: Big Sweaty Foot can apply Daipai to hit targets

**Status:** unsatisfied

**Original requirement:** `Big Sweaty Foot can apply the Daipai effect to hit targets.`

**Current evidence:**
- `.planning/REQUIREMENTS.md` still marks `FOOT-04` as Complete.
- `.planning/phases/03-big-sweaty-foot-item/03-VALIDATION.md` says Apply Daipai on Hit was checked.
- `.planning/phases/05-linked-behavior-and-resources/05-02-PLAN.md` explicitly removed `target.addStatusEffect`.
- Current `src/main/kotlin/com/columbina/yujie/item/BigSweatyFootItem.kt` `postHit` no longer applies `DAIPAI_ENTRY`.

**Impact:** The original “hit target to make them Daipai” weapon loop no longer exists.

**Suggested closure:** Decide whether Phase 5 intentionally supersedes `FOOT-04`. If yes, update requirements and roadmap. If no, restore Daipai application in a non-duplicating way, such as applying a short Daipai I effect without adding an extra damage loop beyond the normal status effect tick.

### YUJI-03: Dongbei Yujie tracks and attacks players

**Status:** unsatisfied

**Original requirement:** `Dongbei Yujie actively tracks players and performs melee attacks after closing distance.`

**Current evidence:**
- Current `DongbeiYujieEntity` target selector excludes `PlayerEntity`.
- Current `setTarget` returns early when the target is a `PlayerEntity`.
- Phase 4 summary says this was changed during UAT to exclude players and other Yujies.

**Impact:** The encounter still has Daipai pressure, but it is not the hostile chase/melee loop described by the roadmap and requirement.

**Suggested closure:** Pick the intended v1 behavior. If Yujie should chase players, restore player targeting while keeping Yujie-vs-Yujie exclusions. If aura-only pressure is intended, update `YUJI-03`, ROADMAP success criteria, and user-facing docs.

### YUJI-07: Controlled night spawning near players

**Status:** partial

**Original requirement:** `At night, the mod attempts to spawn one Dongbei Yujie within 24 blocks of a player while limiting nearby duplicates.`

**Current evidence:**
- Current code uses `BiomeModifications.addSpawn(...)` with vanilla monster spawn rules.
- `canSpawnDongbeiYujie` checks nearest player within 64 blocks, not 24.
- If no player is within 64 blocks, it returns `true`, allowing normal spawn attempts away from players.
- Duplicate limiting exists around the nearest player within 64 blocks.

**Impact:** Duplicate limiting is present, but the “near-player controlled night encounter” is not precise.

**Suggested closure:** Replace or supplement biome spawn with a conservative server tick spawn attempt near players at night, within 24 blocks, with cooldown and nearby Yujie cap.
